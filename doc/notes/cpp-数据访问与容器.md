# C++ 数据访问：数组、指针、引用与容器

数组、指针和引用都与数据访问有关，却承担不同责任。选择时先问：数据长度是否变化，是否需要表示“没有对象”，谁保证对象仍然存在？

## 数组保存数据，指针保存地址

```cpp
int values[3]{10, 20, 30};
int* p = values;
int first = *p;
int second = *(p + 1);
```

数组元素连续存储，合法下标为 `0` 到 `长度 − 1`。指针加 1 按元素大小移动，不是只移动一个字节；指针算术只能在同一个数组及其末尾后一位置的规定范围内进行，末尾后一位置不能解引用。

数组在许多表达式和普通函数参数中会退化为首元素指针，因此下面的函数无法从 `arr` 自己恢复原始数组长度：

```cpp
void increment(int* arr, int size) {
    for (int i = 0; i < size; ++i) {
        ++arr[i];
    }
}
```

传入的长度必须与实际存储相符。指针可以是 `nullptr`，但非空不代表有效：指向已销毁对象的指针同样不可访问。

## 引用表达“使用现有对象”

```cpp
int value = 1;
int& alias = value;
alias = 2;                // 修改 value
```

引用必须初始化，绑定后不能重新绑定。`alias = another` 是给原对象赋值，不是换绑对象。常见参数选择为：

| 参数 | 含义 | 适用情况 |
| --- | --- | --- |
| `T value` | 复制或移动得到参数对象 | 小对象、需要独立值 |
| `T& value` | 借用并允许修改 | 修改调用方对象 |
| `const T& value` | 只读借用 | 避免大对象复制 |
| `T* value` | 保存地址，可为空 | 可选对象或底层接口 |

返回引用需要保证对象在调用结束后仍存在，不能返回局部自动变量的引用。`const` 引用也不能消除悬空问题。

## 字符串优先使用 std::string

C 风格字符串以 `\0` 结束，`"Hello"` 需要 6 个字符空间。缓冲区不足、缺少结束符、用指针 `==` 比较内容，都是常见错误。

```cpp
#include <string>

std::string text = "Hello";
text += " C++";
bool same = text == "Hello C++";
```

`size()` 获取长度，`at()` 检查边界，`c_str()` 用于对接只读 C 字符串接口。对象销毁或某些修改可能使先前取得的字符指针失效，不应长期保存而不检查生命周期。

## vector 管理可变长度数据

```cpp
#include <vector>

std::vector<int> values{1, 2, 3};
values.reserve(20);
values.push_back(4);
for (int& x : values) {
    x *= 2;
}
```

`std::vector` 管理连续的元素存储。`push_back` 追加值，`emplace_back` 用参数构造末尾元素，`pop_back` 删除末尾元素但不返回它。

| 操作 | 改变什么？ |
| --- | --- |
| `size()` | 查询实际元素数量 |
| `capacity()` | 查询已分配空间可容纳多少元素 |
| `reserve(n)` | 预留容量，不创建 n 个元素 |
| `resize(n)` | 改变实际元素数量 |
| `clear()` | 删除元素，通常保留容量 |

`values[0]` 不检查越界；`values.at(0)` 越界时抛异常。空容器不能使用 `front()`、`back()` 或 `pop_back()`。扩容会让原来的元素指针、引用和迭代器失效；中间插入和删除也有相应失效规则。

二维 `vector<vector<int>>` 是“每行各自管理数组”，整体并不保证所有行元素在同一块连续内存中。若接口要求连续矩阵，可使用一维存储加下标映射。

选择原则是：固定数量且需要低层控制时理解数组，日常动态序列优先使用容器；指针和引用借用数据时，仍必须明确其生命周期。
