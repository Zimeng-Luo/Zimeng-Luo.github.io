# Markdown 博客写作：结构、链接与兼容性

个人笔记可以依赖编辑器快捷功能，公开博客则要保证读者在页面上看到完整结构、有效链接和清楚说明。本文保留常用 Markdown，减少对特定笔记软件的依赖。

## 用标题组织阅读

每篇正文使用一个一级标题 `#`，主要章节使用 `##`，需要时再用 `###`。标题表达内容关系，不用字体大小代替逻辑层级。段落之间留空行，代码示例之后解释输入、输出与边界。

```markdown
# 文章标题

先说明文章解决什么问题。

## 核心概念

说明定义与一个例子。
```

文章的标题层级与文件目录层级是两件事。博客文章直接放在指定栏目下，不需要为每种细分主题创建子目录；分类表达栏目，标签表达知识关联。

## 列表、代码与引用

无序列表用 `-`，有序步骤用数字加点。列表项在语义上应平行；不要把整篇解释都拆成一句话一条。任务列表 `- [ ]` 属于扩展语法，目标平台的实际呈现可能不同。

代码块标明 `python`、`bash` 等语言，行内代码使用反引号。需要展示含三反引号的 Markdown 时，可用四反引号包住外层示例。

引用块使用 `>`，表明引文或补充信息，而不是把正文全部缩进。VitePress 支持自己的提示容器：

```markdown
::: tip 使用条件
说明一个有实际帮助的条件。
:::
```

Obsidian 的 `> [!NOTE]` 等提示语法并非所有 Markdown 平台通用，迁移时应使用平台支持的形式。

## 链接与图片要有实际目标

```markdown
[相关笔记](./git基础.md)
![图片内容说明](/blog/bg02.jpg)
```

相对路径按当前文档位置解析，根路径从站点根开始。图片替代文本说明图像内容与作用，不能只写 `image.png`。`[[双向链接]]`、`![[附件]]` 和 `|宽度` 是 Obsidian 扩展，不能原样假定会在博客正常工作。

附件未随资料提供时，先用文字或表格重写图中必要结论，不能保留指向不存在文件的占位图。需要图片时使用已存在且允许引用的资源。

## 表格用于真正的比较

表头下面有分隔行，列数保持一致。单元格里的竖线可能被当成分列符，即使处在行内代码或公式里也需按解析器规则转义；必要时把复杂公式移到表格外。

粗体用 `**文字**`，删除线等扩展取决于渲染器。HTML 标签要正确闭合，例如 `<u>文字</u>`；`==高亮==` 并非通用 Markdown。

## 发布前检查

核对文章元信息、标题、日期、分类、标签和封面；确认相对链接有效，示例代码的语言正确，代码围栏完整，图片能找到。公式语法能否渲染取决于站点配置，不应因为笔记软件中能显示，就直接认为博客也能显示。

优先保存稳定、能独立阅读的文字结构，让读者不必装同一个编辑器或掌握同一套插件才能理解文章。
