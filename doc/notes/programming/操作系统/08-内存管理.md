# 内存管理

## 核心摘要

内存管理负责把程序装入内存、完成逻辑地址到物理地址的转换，并在多进程之间提供分配、保护和共享机制。重点包括地址绑定、MMU、交换、连续分配、分页和分段。

## 编译、链接与装入

程序从源代码到可执行文件通常经历预处理、编译、汇编和链接。

```bash
gcc -E -o hello.i hello.c   # 预处理
gcc -S -o hello.s hello.c   # 编译为汇编
gcc -c -o hello.o hello.c   # 汇编为目标文件
gcc -o hello hello.c        # 链接为可执行文件
```

程序运行时，可执行文件被装入内存，形成进程地址空间。

## 地址类型

| 地址 | 含义 |
| --- | --- |
| 符号地址 | 程序中的变量名、函数名 |
| 逻辑地址 | CPU 生成的地址，又称虚拟地址 |
| 物理地址 | 内存硬件实际访问的地址 |

## 地址绑定

地址绑定是把程序中的地址映射到内存地址的过程。

| 时机 | 特点 |
| --- | --- |
| 编译时绑定 | 编译时确定装入地址，位置固定 |
| 装入时绑定 | 装入内存时确定物理地址 |
| 运行时绑定 | 运行中可移动，需要硬件支持 |

现代系统通常使用运行时绑定，由 MMU 完成地址转换。

## MMU 与内存保护

MMU 是把逻辑地址映射为物理地址的硬件。基地址寄存器和界限寄存器可用于界定进程可访问的内存范围，防止用户进程访问系统区域或其他进程空间。

## 交换

交换是把进程暂时从内存移到磁盘，再在需要时换回内存的机制。它可以提高多道程序程度，但磁盘 I/O 开销较大。

## 连续内存分配

连续分配要求每个进程占用一段连续物理内存。

| 方法 | 特点 |
| --- | --- |
| 固定分区 | 分区大小固定，可能产生内部碎片 |
| 动态分区 | 按需分配，可能产生外部碎片 |

动态分区常见策略包括首次适应、最佳适应和最坏适应。外部碎片可通过紧缩缓解，但紧缩需要进程可重定位。

## 分页

分页把逻辑内存分为页，把物理内存分为页框。页表记录页号到页框号的映射。

| 优点 | 说明 |
| --- | --- |
| 避免外部碎片 | 页框可离散分配 |
| 便于保护共享 | 页表项可记录权限和共享状态 |
| 支持虚拟内存 | 未使用页面可暂不装入内存 |

分页可能产生内部碎片，且页表访问会带来额外开销，因此常配合 TLB 加速地址转换。

## 分段

分段按程序逻辑单位划分地址空间，如代码段、数据段、栈段。段表记录段基址和段长。

| 对比 | 分页 | 分段 |
| --- | --- | --- |
| 划分依据 | 固定大小 | 逻辑单位 |
| 用户可见性 | 通常不可见 | 更接近程序结构 |
| 碎片 | 可能内部碎片 | 可能外部碎片 |

实际系统常结合分页和分段思想，以兼顾地址空间抽象、保护和分配效率。
