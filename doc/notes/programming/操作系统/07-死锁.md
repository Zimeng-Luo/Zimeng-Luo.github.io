# 死锁

## 核心摘要

死锁是指一组进程相互等待对方持有的资源，导致所有进程都无法继续推进。处理思路包括预防、避免、检测与恢复，也可以在某些系统中选择忽略。

## 死锁定义

进程使用资源的一般顺序是申请、使用、释放。当一组进程中的每个进程都等待只能由组内其他进程触发的事件时，这组进程处于死锁状态。

## 四个必要条件

| 条件 | 含义 |
| --- | --- |
| 互斥 | 一个资源实例同一时刻只能被一个进程使用 |
| 占有并等待 | 进程已持有资源，同时等待新资源 |
| 非抢占 | 资源不能被强制夺走，只能由持有者释放 |
| 循环等待 | 存在进程资源等待环 |

四个条件同时成立才可能发生死锁。

## 资源分配图

资源分配图包含进程节点、资源节点、申请边和分配边。

| 边 | 含义 |
| --- | --- |
| 申请边 `Pi -> Rj` | 进程 `Pi` 正在请求资源 `Rj` |
| 分配边 `Rj -> Pi` | 资源 `Rj` 的实例已分配给 `Pi` |

若每类资源只有一个实例，图中有环意味着死锁；若资源有多个实例，有环只表示可能死锁。

## 死锁处理方法

| 方法 | 思路 |
| --- | --- |
| 预防 | 破坏四个必要条件之一 |
| 避免 | 分配前判断是否会进入不安全状态 |
| 检测 | 允许死锁发生，再周期性检测 |
| 恢复 | 发现死锁后终止进程或抢占资源 |
| 忽略 | 认为死锁概率低，由人工或上层处理 |

## 死锁预防

| 破坏条件 | 方法 |
| --- | --- |
| 互斥 | 只对可共享资源有效，通常难破坏 |
| 占有并等待 | 进程一次性申请全部资源，或申请新资源前释放已持有资源 |
| 非抢占 | 请求失败时释放已持有资源，之后重试 |
| 循环等待 | 为资源编号，进程按递增顺序申请 |

## 死锁避免

死锁避免需要提前知道进程最大资源需求，动态判断分配后系统是否仍处于安全状态。

| 算法 | 适用 |
| --- | --- |
| 资源分配图算法 | 每类资源只有一个实例 |
| 银行家算法 | 每类资源可有多个实例 |

安全状态表示系统存在某种安全序列，使所有进程都能按顺序完成；不安全状态不一定死锁，但可能进入死锁。

## 死锁检测与恢复

检测算法根据当前资源分配、可用资源和进程请求判断是否存在无法推进的进程集合。

恢复方法包括：

1. 终止所有死锁进程。
2. 按代价逐个终止进程，直到解除死锁。
3. 抢占资源并回滚进程状态。

选择牺牲进程时通常考虑优先级、已运行时间、剩余工作量、占用资源数量和回滚成本。
