# 进程同步

## 核心摘要

进程同步用于保证并发进程访问共享数据时的一致性。核心问题是临界区互斥，常见工具包括硬件原子指令、互斥锁、信号量和管程。

## 背景

多个进程或线程共享数据时，执行顺序不确定可能导致竞争条件。竞争条件是指多个执行流同时读写共享数据，最终结果依赖不可控的执行时序。

## 临界区问题

临界区是访问共享数据的代码段。每个进程围绕临界区通常分为进入区、临界区、退出区和剩余区。

正确的临界区解法需要满足：

| 条件 | 含义 |
| --- | --- |
| 互斥 | 同一时刻最多一个进程进入临界区 |
| 进步 | 没有进程在临界区时，应能选择一个等待者进入 |
| 有限等待 | 进程提出请求后不能无限期等待 |

## Peterson 算法

Peterson 算法是两个进程的软件互斥算法，使用 `flag` 表示进入意愿，用 `turn` 表示谦让对象。它展示了互斥、进步和有限等待的逻辑，但现代 CPU 的乱序执行和内存模型会影响其直接可用性。

## 硬件同步

硬件提供原子指令支持互斥。

| 方法 | 说明 |
| --- | --- |
| 禁用中断 | 单处理器可用，多处理器不适合 |
| Test-and-Set | 原子测试并设置锁变量 |
| Compare-and-Swap | 比较旧值，匹配时原子替换为新值 |

硬件原子指令常用于实现自旋锁、互斥锁和更高级同步原语。

## 信号量

信号量是整数同步变量，只能通过原子操作 `wait(P)` 和 `signal(V)` 修改。

| 类型 | 用途 |
| --- | --- |
| 二元信号量 | 实现互斥锁 |
| 计数信号量 | 管理多个同类资源实例 |

使用信号量要避免死锁、饥饿和错误的 P/V 顺序。

## 经典同步问题

| 问题 | 关注点 |
| --- | --- |
| 生产者-消费者 | 缓冲区空/满与互斥访问 |
| 读者-写者 | 多读并发与写互斥 |
| 哲学家进餐 | 资源竞争、死锁和饥饿 |

## 管程

管程把共享数据和对数据的操作封装在一起，并保证同一时刻只有一个进程在管程内执行。条件变量用于让进程在条件不满足时等待，在条件满足时被唤醒。

管程比裸信号量更结构化，适合实现复杂同步逻辑。
