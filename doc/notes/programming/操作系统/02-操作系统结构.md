# 操作系统结构

## 核心摘要

操作系统通过服务、用户界面、系统调用和系统程序向外提供能力；内部结构常见形式包括简单结构、分层结构、微内核、模块化和虚拟机。

## 操作系统服务

| 服务 | 说明 |
| --- | --- |
| 程序执行 | 将程序载入内存并运行 |
| I/O 操作 | 为程序提供统一的设备访问接口 |
| 文件系统操作 | 创建、删除、读写文件和目录 |
| 通信 | 支持进程间或网络通信 |
| 错误检测 | 检测 CPU、内存、I/O、程序错误 |
| 资源分配 | 为并发作业分配 CPU、内存、设备 |
| 统计与保护 | 记录资源使用并控制访问权限 |

## 用户界面

| 界面 | 特点 |
| --- | --- |
| CLI | 命令行交互，适合脚本和系统管理 |
| GUI | 图形界面，适合普通用户交互 |
| Batch | 批处理方式，适合无需人工干预的作业 |

Shell 是用户和操作系统服务之间的命令解释器，本身通常不是内核的一部分。

## 系统调用

系统调用是操作系统面向程序提供的编程接口。应用一般通过 API 调用库函数，再由库函数触发具体系统调用。

```text
应用程序 -> API/库函数 -> 系统调用 -> 内核服务 -> 硬件资源
```

### 参数传递方式

| 方式 | 说明 |
| --- | --- |
| 寄存器 | 参数少时最快 |
| 内存块/表 | 参数多时传递地址 |
| 栈 | 按调用约定压栈传参 |

### 常见系统调用分类

| 类别 | 示例 |
| --- | --- |
| 进程控制 | 创建、终止、等待进程 |
| 文件管理 | 打开、关闭、读写文件 |
| 设备管理 | 请求、释放、读写设备 |
| 信息维护 | 获取时间、系统信息、进程属性 |
| 通信 | 管道、共享内存、消息传递、Socket |
| 保护 | 权限检查、访问控制 |

## 系统程序

系统程序为用户提供更高层的便利功能，如文件管理、状态查询、文本处理、编译链接、程序装载、通信工具和后台服务。

## 操作系统设计与实现

设计操作系统时需要区分机制和策略。

| 概念 | 含义 |
| --- | --- |
| 机制 | 系统“能做什么”，如上下文切换、页表映射 |
| 策略 | 系统“怎么选择”，如调度算法、页面置换算法 |

机制应尽量稳定通用，策略可以按场景调整。

## 操作系统结构类型

| 结构 | 特点 |
| --- | --- |
| 简单结构 | 功能耦合紧，早期系统常见 |
| 分层结构 | 每层只依赖下层，便于理解和维护 |
| 微内核 | 内核只保留最基本功能，其他服务放到用户态 |
| 模块化结构 | 内核核心加可加载模块，兼顾性能和扩展性 |
| 混合结构 | 结合多种结构，现代通用系统常见 |

## 虚拟机

虚拟机通过虚拟化技术在同一硬件上运行多个隔离的操作系统实例。优点是隔离性强、便于测试和资源复用；代价是需要额外的虚拟化管理开销。
