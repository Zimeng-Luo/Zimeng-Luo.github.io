# C++ 访问控制、封装与数据抽象

## 核心摘要

访问控制决定成员可见范围。封装把数据和操作收进类里，只暴露稳定接口。数据抽象强调“只看能做什么，不看怎么做”，本质是接口和实现分离。

## 访问修饰符

| 修饰符 | 类内 | 派生类 | 类外 | 常见用途 |
| --- | --- | --- | --- | --- |
| `public` | 可访问 | 可访问 | 可访问 | 对外接口 |
| `protected` | 可访问 | 可访问 | 不可访问 | 供继承复用 |
| `private` | 可访问 | 不可直接访问 | 不可访问 | 内部数据与实现 |

`class` 默认成员访问权限是 `private`，`struct` 默认是 `public`。

## 封装

封装就是把数据隐藏起来，只通过成员函数操作对象。

### 要点

| 做法 | 目的 |
| --- | --- |
| 成员变量设为 `private` | 防止外部直接破坏对象状态 |
| 提供 `public` 成员函数 | 暴露稳定、可控的操作入口 |
| 必要时使用 `protected` | 让派生类复用基类能力 |
| 只读函数加 `const` | 保证函数不修改对象状态 |

```cpp
class Account {
private:
    double balance = 0.0;

public:
    void deposit(double amount) {
        if (amount > 0) {
            balance += amount;
        }
    }

    double getBalance() const {
        return balance;
    }
};
```

## 数据抽象

数据抽象是只向外提供必要接口，隐藏内部实现细节。

### 直观理解

像电视机一样，用户只关心开关、频道、音量，不需要知道内部电路如何工作。

### C++ 中的体现

C++ 用类来定义抽象数据类型（ADT）。类的公有成员构成接口，私有成员保存实现细节。

```cpp
#include <iostream>
using namespace std;

class Adder {
public:
    Adder(int i = 0) : total(i) {}

    void addNum(int number) {
        total += number;
    }

    int getTotal() const {
        return total;
    }

private:
    int total;
};

int main() {
    Adder a;
    a.addNum(10);
    a.addNum(20);
    a.addNum(30);
    cout << "Total " << a.getTotal() << endl;
    return 0;
}
```

## 好处

- 保护内部状态，减少误用
- 接口稳定后，内部实现可以替换
- 代码更易维护、测试和复用

## 设计原则

抽象的核心是分离接口和实现。对外只暴露必要方法，底层数据结构或算法可以变化，只要接口不变，使用方通常不需要改动。
